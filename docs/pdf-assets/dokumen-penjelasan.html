Pemahaman Masalah

Latar belakang. Mencari tukang, AC service, atau jasa bersih di Indonesia masih mengandalkan grup WhatsApp dan mulut-ke-mulut. Risiko besar menghantari kedua sisi: pelanggan takut ditipu, penyedia jasa kesulitan mendapat order.

1.Tiga Pain Point Utama

01

Sulit Membanding Harga

Tidak ada transparansi harga. Pelanggan harus bertanya satu per satu ke banyak tukang hanya untuk mengetahui kisaran harga wajar.

02

Takut Ditipu

Tidak ada riwayat rating dan ulasan. Pelanggan menyerahkan kunci rumah kepada orang asing tanpa jejak reputasi apa pun.

03

Provider Daerah Tak Terlihat

Penyedia jasa di kota kecil seperti Pangkal Pinang hanya mengandalkan spanduk — tidak ditemukan pencarian nasional.

2.Sistem Navigasi & Orientasi

  • Breadcrumb di semua halaman — “Beranda › Jasa › Detail Jasa › Checkout”, pengguna selalu tahu posisinya.

User Experience — Bukti Implementasi

4.Form & Validasi Tanpa Kejutan

  • Validasi inline (react-hook-form + Zod): pesan error muncul per-field saat blur, bukan setelah submit gagal.
  • Checkout 2 langkah jujur — Detail → Alamat & Bayar; placeholder alamat berisi contoh format benar + chip provinsi.
  • Chip deadline — Besok / 2 hari / Minggu, bukan input tanggal bebas yang membingungkan.

5.Feedback Instan & Optimistic UI

  • Simpan jasa (heart) — animasi pulse + konfirmasi visual seketika, rollback otomatis bila gagal.
  • Kanban drag & drop — status pesanan berubah seketika di layar; sinkronisasi server di belakang.
  • Toast + notifikasi tergrup — pusat notifikasi dengan grouping & tandai-sudah-dibaca, live region untuk screen reader.
  • Micro-interaction konsisten — chip filter menekan (scale 0.95), hover state di semua elemen interaktif.

2.Keamanan (Defense-in-Depth)

🔐 Serangan Diantisipasi

• CSRF — pola double-submit cookie+header
• Brute force — rate limit token bucket, 13 aturan per endpoint
• Role bypass — middleware whitelist + guard per rute
• XSS — React escaping, tanpa dangerouslySetInnerHTML pada konten user

🔐 Praktik Data

• Password bcrypt, JWT httpOnly 30 hari
• Validasi Zod di sisi server pada semua input API
• ID provider diverifikasi ownership sebelum mutasi
• Secret via env vars — nol credential di repo
