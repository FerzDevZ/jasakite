# MEMORY — Invariants & Post-Mortems

### 🧠 Learned Invariants & Failure Post-Mortems

- **[26-09-29 · Perf/Lighthouse]** `pkill -f chrome` membunuh shell sendiri karena command line shell memuat teks `--chrome-flags` (match pola pkill). → **Invariant Rule**: selalu pakai pola self-exclusion `pkill -f "chrome.headles[s]"`.
- **[26-09-29 · Perf/Lighthouse]** Run LH kosong/error CHROME_INTERSTITIAL: server `next start` mati antar sesi shell + preflight tidak ada. → **Invariant Rule**: dalam SATU command: kill port → start server → **loop preflight curl sampai 200** → sleep 10 → loop LH → kill; verifikasi ukuran JSON (~500KB = valid, ~200KB = error).
- **[26-09-29 · Perf/Harness]** TBT antar-run berayun 631ms–8s pada build identik; penyebab: proses chrome liar + beban CPU aplikasi lain (load avg 9.13, FCP pun ikut naik). → **Invariant Rule**: sebelum menarik kesimpulan CWV, cek `uptime` & proses (%CPU tinggi); saat load > ~5, angka absolut tidak bermakna — laporkan sebagai terkontaminasi, jangan "optimasi gagal".
- **[26-09-29 · React/DeferredLoad]** `requestIdleCallback` untuk muat chunk ~34KB (sonner) justru **menaikkan TBT**: idle tercapai tepat setelah hydrate, eval masuk jendela quiet-window TTI. → **Invariant Rule**: defer-interaksi = trigger `pointerdown/keydown/touchstart` + timeout fallback ≥8s, BUKAN rIC; toast & UI post-interaksi adalah kandidat ideal.
- **[26-09-29 · LCP/SSR]** LCP /services ternyata chip kategori (Render Delay 89%), bukan gambar — data di-fetch client setelah hydrate; dan tile ke-2 grid 2-kolom dengan `loading="lazy"` bisa jadi LCP terakhir ter-paint. → **Invariant Rule**: baca audit `largest-contentful-paint-element` (element + fase) sebelum menebak; SSR-kan data above-the-fold (initialData TanStack + modul query bersama dengan API) dan `priority={i < kolom-baris-pertama}` untuk gambar tile.
- **[26-09-29 · Next.js/Build]** `next build` memuntah HTML satu-baris: `grep -c "marker"` menghasilkan 0/1 — bukan jumlah kemunculan. → **Invariant Rule**: hitung dengan `grep -o | wc -l`, dan gunakan marker DOM (`<button aria-pressed`, `<img src="/_next/image`) untuk memastikan konten benar-benar dirender SSR, bukan hanya payload RSC.
- **[26-09-30 · Wallet/Kode]** Test regex `not.toMatch(/[01OIL5S]/)` gagal pada kode top-up: prefix "JK-TOP" memang memuat "O" — larangan karakter tertukar hanya berlaku untuk bagian acak. → **Invariant Rule**: saat menguji alfabet kode berprefix, uji `code.slice(prefix.length)`, bukan string utuh; prefix itu sendiri dikecualikan dari aturan alfabetnya.
- **[26-09-30 · Wallet/ProofImage]** Loop kualitas `quality -= 0.1` dengan `Math.round(quality * 10) / 10` menghasilkan langkah [0.8, 0.7, ...] dan berhenti sebelum lantai 0.4 — nilai kontrol ikut ter-round (0.75→0.8), dan float 0.65 melompati bound. → **Invariant Rule**: jangan pernah membulatkan variabel kontrol loop floating-point; round hanya nilai output yang di-push, dan batasi loop dengan epsilon (`quality >= floor - 0.001`).
- **[26-09-30 · Wallet/ProofImage]** Validator klien pakai `startsWith("data:image/jpeg;base64,")` sehingga sampah setelah payload base64 lolos di klien padahal regex full-match di API menolaknya. → **Invariant Rule**: validator klien yang mencerminkan schema API wajib memakai pattern full-match yang sama persis (regex `/^data:image\/(jpeg|png|webp);base64,[A-Za-z0-9+/=]+$/`), bukan cek prefix yang lebih longgar.
- **[26-10-04 · PDF/Artifacts]** Hitung halaman PDF via regex `/Type /Page\b` memberi hasil berbeda antar-run (13 vs 20) untuk HTML yang nyaris identik, dan ukuran file ikut melompat — regex rawan salah baca struktur objek Skia/PDF; `pdfinfo` (poppler) membaca `/Count` root page tree dan menegaskan 20 halaman yang stabil 2× regenerate. → **Invariant Rule**: verifikasi artefak PDF (halaman/ukuran) hanya dengan `pdfinfo`, bukan regex pada byte mentah; regenerasi ulang & bandingkan stabilitasnya sebelum menyatakan selesai, dan tulis file HTML besar secara bertahap (skeleton + str_replace) agar tidak terpotong batas token.
- **[26-10-04 · CodeSearch/Tooling]** `code_search` pola `application/ld+json` dan `ld\+json|JSON-LD` balik "0 matches", sehingga sempat disimpulkan data terstruktur belum ada — padahal `app/layout.tsx` (siteJsonLd), `app/faq/page.tsx`, dan `app/service/[slug]/page.tsx` sudah memuatnya; pola wildcard `ld.json` + `grep -rn` terminal baru menemukan kelimanya. → **Root Cause**: karakter regex khusus (`+`, escape) pada pola membuat tool false-negative secara senyap. → **Invariant Rule**: jangan menyimpulkan "fitur belum ada" dari satu hasil nol; ulangi dengan pola wildcard sederhana (`ld.json`) atau `grep` terminal sebelum mengklaim, terutama untuk pola yang memuat `+` atau bracket path.
- **[26-10-05 · OG/Route-Convention]** `app/service/[slug]/opengraph-image.tsx` **tidak perlu** didaftarkan di `generateMetadata` — tag `og:image`/`twitter:image` tetap disuntik walau objek `openGraph` di `generateMetadata` tidak punya `images`; tapi di `next dev` URL-nya memakai origin dev (`http://localhost:4317/...`) sedangkan di `next start` ia diresolusi terhadap `metadataBase` (`https://jasakite.id/...`). → **Invariant Rule**: verifikasi URL absolut metadata selalu di build produksi (`next build && next start`) — hasil dev menyesatkan soal host, bukan soal ada/tidaknya tag.
- **[26-10-05 · OG/Foto-Preflight]** Kartu OG pertama kali ter-render TANPA foto padahal URL foto hidup: preflight `AbortSignal.timeout(4_000)` kalah oleh TLS+DNS dingin ke `images.unsplash.com` yang diukur **5,6 dtk** (hangat <1 dtk), dan kegagalan itu senyap (fallback monogram). Terdeteksi hanya dengan mengukur panel gambar PNG hasil render (stddev area crop 440x510+700+60: 0,02 = monogram vs 0,16 = foto), bukan dari status HTTP yang tetap 200. → **Invariant Rule**: timeout preflight aset remote harus ≥8 dtk untuk koneksi dingin; dan verifikasi "apakah gambar benar-benar masuk ke render" harus mengukur piksel artefak (stddev crop via ImageMagick), sebab route sukses 200 bisa berarti fallback yang dipakai.
- **[26-10-05 · OG/Kartu-Penyedia]** Semua avatar seed ada di `i.pravatar.cc`: **curl** ke host itu timeout (http=000, 10 dtk) sehingga sempat disimpulkan "host mati → kartu cuma monogram", padahal **fetch Node** (jalur yang dipakai preflight/satori) sukses 200 dalam 289 ms dan fotonya benar-benar ter-render. → **Invariant Rule**: jangan pernah menyimpulkan reachability aset dari `curl` saja — jalur runtime adalah `fetch` Node; buktikan isi kartu dengan histogram warna panel hasil render (foto = sebaran abu `#5F5F5F`/`#9F9F9F`, monogram = latar datar `#1C1917` + oranye `#6A3B1B`), bukan dari status HTTP yang tetap 200 di kedua kasus.
- **[26-10-05 · OG/Tahan-Gagal]** Menguji cabang `catch` pada route OG tidak butuh database yang benar-benar rusak: jalankan build produksi dengan `DATABASE_URL="mongodb://127.0.0.1:1/none"` → kedua route tetap `200 image/png` 1200×630 (kartu fallback) dan mencatat `[og/service]`/`[og/provider] gagal memuat` alih-alih 500 tanpa preview. → **Invariant Rule**: untuk route og:image, kegagalan data (DB/DNS/id tidak valid) wajib memakai kartu merek + `console.error`, bukan 500; verifikasi cabang itu lewat override env pada `next start`, dan cek satu URL halaman yang gagal transien dengan mengulang sebelum menyimpulkan route rusak (500 di satu run bisa dari DNS SRV Atlas, bukan kode).
- **[26-10-04 · Tooling/Verifikasi]** `nohup npm run dev &` dalam perintah SYNC selesai "READY" tapi fetch berikutnya `ECONNREFUSED` — server dibunuh cleanup tool saat command selesai; dan 2× cek runtime gagal karena asersi cek sendiri yang salah (mengharap link dari BASE port padahal kode memakai SITE_URL kanonik; mem-parse teks multi-baris sebagai URL). → **Root Cause**: background anak dari perintah SYNC tidak bertahan setelah tool selesai; dan menulis ekspektasi cek dari asumsi, bukan dari konvensi kode. → **Invariant Rule**: orkestrasi start → preflight → cek → kill dalam SATU perintah (atau mode BACKGROUND) dengan exit code disimpan ke variabel sebelum kill; kunci asersi pada konvensi repo (SITE_URL kanonik) dan cetak nilai aktual dulu sebelum membulatkan ke assert.
- **[26-10-07 · OG/Test-Piksel]** Ambang simpangan baku TIDAK bisa memisahkan panel berfoto dari panel monogram: huruf monogram 150px berwarna oranye di atas latar `#1C1917` menaikkan stddev crop panel sampai **34,9/255**, sedangkan foto 60–90 — asumsi "monogram ≈ 5" dari foto asli (yang hampir menutupi seluruh panel) salah diterapkan ke kartu fallback. → **Root Cause**: mengukur "kerataan panel" dengan metrik yang ikut terpengaruh objek di atas latar, bukan mengukur kerataannya sendiri. → **Invariant Rule**: pembeda aman = **pangsa warna dominan** pada crop panel (monogram ≈ 0,98 karena satu plat datar; foto < 0,01), bukan simpangan baku; dan setiap test piksel/visual baru WAJIB diuji mutasi (paksa panel jadi monogram → 0,0064 naik jadi 0,9890, test harus merah) sebelum diklaim sebagai guard.
- **[26-10-11 · OG/Preflight-Test]** Test "host yang tidak bisa dihubungi" memakai `http://127.0.0.1:1/...` selalu hijau, tapi undici menolaknya sebagai **`bad port`** (port 1 ada di daftar port terlarang fetch spec) sebelum menyentuh jaringan — jadi cabang kegagalan jaringan tidak pernah benar-benar diuji, dan log kegagalan hanya bisa menulis `fetch failed` tanpa kode penyebab. → **Root Cause**: menyamakan "port aneh" dengan "koneksi ditolak". → **Invariant Rule**: untuk mensimulasikan host mati, pakai port yang benar-benar tertutup (buka server → catat port → tutup → baru dipakai) sehingga `error.cause.code` = `ECONNREFUSED`; asersi log harus memeriksa kode penyebab (`cause.code`), bukan `error.message` yang cuma "fetch failed".
- **[26-10-11 · OG/Preflight-Cache]** Setiap render kartu mengulang HEAD preflight (sampai 8 dtk) tanpa cache, dan `catch {}` menelan kegagalannya tanpa satu baris log — foto bisa hilang di produksi tanpa jejak apa pun padahal route tetap `200 image/png`. → **Root Cause**: preflight diperlakukan sebagai panggilan murni per-permintaan, dan cabang degraded dianggap "sudah ditangani" cukup karena ada fallback monogram. → **Invariant Rule**: cache hasil preflight per URL (sukses 10 mnt; gagal hanya 30 dtk supaya blip CDN tidak menyembunyikan foto lama) plus dedupe in-flight agar N crawler bersamaan hanya memicu satu HEAD; setiap cabang degraded wajib satu baris log terstruktur berisi URL + alasan + `cause.code`. Verifikasinya di runtime: jalankan `next start` dengan `NODE_OPTIONS=--require` preload yang menggagalkan DNS host CDN (DB dibiarkan hidup), lalu hitung baris log — dua kartu berbeda yang berbagi satu URL foto harus menghasilkan tepat **1** baris, dan panelnya harus terukur monogram (0,9890) bukan 500.
- **[26-10-12 · OG/Test-Metrik-Panel]**: Pengukuran pangsa warna dominan panel kartu (`PANEL_CROP = {left:712, top:72, width:416, height:486}`) hidup hanya di dalam satu test, jadi angkanya tidak terikat ke tata letak kartu dan tidak bisa dipakai kartu lain; sekaligus ambang "foto < 0,05" gampang salah dibaca sebagai pendeteksi semua foto, padahal foto berlatar rata (88 baris bidang datar dari 512) terukur **0,1564** — di pita antara 0,05 dan ambang monogram 0,9890. → **Root Cause**: crop dan ambang diketik ulang di test alih-alih diturunkan dari geometri kartu dan dari hasil kalibrasi yang sama; metrik dengan dua kutub (foto bertekstur / monogram) dianggap punya dua kemungkinan saja. → **Invariant Rule**: crop pengukuran harus diturunkan dari konstanta tata letak kartu (`SHARE_CARD_PADDING` + `SHARE_CARD_TEXT_COLUMN_WIDTH` + `SHARE_CARD_SIZE`, inset tepi border 12px) dan ambangnya diekspor dari satu helper bersama (`tests/helpers/og-card-panel.ts`); verdict panel itu tri-state (`photo` < 0,05 · `inconclusive` 0,05–0,5 · `monogram` > 0,5) dan ambang monogram tidak boleh diturunkan sampai menyentuh pita tersebut — foto berlatar rata wajib di-assert tetap > 0,05 dan < 0,5 supaya batas ini terlihat saat fixture berubah.
- **[26-10-12 · OG/Visual-Baseline]** Baseline visual kartu OG 1200×630 ditulis lewat `sharp(...).png({ compressionLevel: 9 })` dan hasilnya langsung tidak cocok dengan dirinya sendiri: sharp **mengaktifkan PNG berpalet secara diam-diam pada level 9**, dan kuantisasinya terukur mengubah 49.599 byte sampai 27/255 (`isPalette: true`, `channels: 3`). → **Root Cause**: menganggap "PNG" berarti "lossless", padahal opsi encoder bisa menyalakan kuantisasi tanpa peringatan. → **Invariant Rule**: setiap re-encode PNG yang hasilnya akan dijadikan pembanding piksel wajib `palette: false`, lalu dibuktikan dengan membandingkan hasil dekode (`raw()`) sebelum-sesudah — bukan dengan ukuran file; re-encode lossless level 9 memotong 852 KB → 470 KB (45%) dengan `palette: false`.
- **[26-10-12 · OG/Blind-Spot-Crop]** Metrik piksel panel hanya melihat satu crop: menggeser `SHARE_CARD_PADDING` 60 → 64 (seluruh isi kartu bergeser 4px, termasuk panel) membuat **keempat** test panel tetap hijau karena crop-nya ikut bergeser, sementara baseline penuh mendeteksi 5,1–19,9% piksel berbeda. Perubahan `paddingRight` kolom teks yang memicu wrap juga lolos dari panel tapi tertangkap baseline. → **Root Cause**: metrik wilayah mengukur *isi* wilayah, bukan *letak* wilayah. → **Invariant Rule**: guard piksel yang memakai crop wajib didampingi baseline utuh-kartu (perbandingan piksel penuh dengan toleransi kanal 8/255 dan ambang 0,05% = 378 dari 756.000), dan setiap guard baru diuji mutasi lewat dua arah: ubah isi wilayah (panel) DAN geser tata letak (padding) — render satori terukur deterministik (0/756.000 piksel berbeda pada dua run berturut), jadi kegagalan baseline selalu berarti kartunya berubah.
- **[26-10-12 · OG/Pemantauan-Preflight]** Fallback foto OG yang mengembalikan `200 image/png` tidak bisa dipantau lewat metrik apa pun: tidak ada error rate, tidak ada halaman rusak — satu-satunya jejak adalah baris log, dan itu mengharuskan seseorang membedahnya. Setelah hitungan per alasan/host ditambahkan (dibaca lewat endpoint admin, per proses), runtime terbukti: dengan DNS dua host CDN dibuat gagal, dua kartu tetap `200 image/png` sementara laporan berubah jadi `failing` dengan `network 2` + `fetch failed (ENOTFOUND)`, dan tiga render kartu yang sama menghasilkan **1** percobaan + `dilayani dari cache 2` + 1 baris log. → **Root Cause**: jalur degraded yang "berhasil secara HTTP" dianggap selesai begitu ada fallback, tanpa menyisakan angka yang bisa dibaca mesin. → **Invariant Rule**: setiap fallback yang menyamarkan kegagalan di balik status sukses wajib punya hitungan yang bisa dibaca (bukan hanya log), dan hitungan itu harus memisahkan *permintaan* dari *percobaan* — cache dan dedupe tidak boleh menaikkan angka percobaan, jika tidak angkanya berhenti mewakili beban ke CDN; sertakan `scope` (per proses vs global) di laporannya supaya angka satu instance tidak dibaca sebagai total platform.
- **[26-10-14 · Vercel/Schema-Swap]** `scripts/vercel-prepare.js` menyalin `prisma/schema.mongo.prisma` menimpa `prisma/schema.prisma` pada setiap build Vercel (karena DATABASE_URL selalu mongo), dan salinan itu berhenti diperbarui: model `OgPhotoPreflightSnapshot` tidak ada di sana. Build tetap hijau, typecheck hijau, dan test lokal hijau (Prisma di-mock) — yang hilang hanya fitur di produksi: `prisma.ogPhotoPreflightSnapshot` = `undefined` di jalur render kartu OG dan endpoint admin. → **Root Cause**: dua sumber kebenaran schema yang wajib dijaga identik dengan tangan, ditambah langkah build yang MENULIS berkas schema alih-alih memeriksanya. → **Invariant Rule**: satu schema saja (`prisma/schema.prisma`); langkah build boleh memeriksa env dan menolak (`scripts/vercel-preflight.js`) tapi tidak pernah menyalin schema; `tests/prisma-schema-parity.test.ts` menolak salinan `schema*.prisma` yang isinya berbeda DAN setiap `prisma.<model>` yang dipakai kode tapi tidak ada di schema (keduanya sudah diuji mutasi: merah saat dilanggar, hijau saat dipulihkan).
- **[26-10-14 · OG/Prerender-Static]** `app/services/opengraph-image.tsx` diprerender Next saat `next build` — PNG-nya tertulis ke `.next/server/app/services/opengraph-image.body` dengan `initialRevalidateSeconds: false` di `.next/prerender-manifest.json`. Kartu tetap "berhasil" (200, 1200×630), jadi tidak ada yang gagal; yang terjadi adalah angka "N jasa aktif" beku sejak build, dan build tanpa database yang terjangkau akan memanggang kartu fallback (tanpa angka) secara PERMANEN, tanpa error apa pun di runtime karena tidak ada permintaan yang menyentuh database. → **Root Cause**: rute OG tanpa parameter dinamis dianggap statis oleh Next, sedangkan isinya berasal dari agregasi database. → **Invariant Rule**: setiap rute OG yang membaca DB tanpa segmen dinamis wajib `export const dynamic = "force-dynamic"` (atau `revalidate` berhingga), dibuktikan lewat `next build` dengan memeriksa `prerender-manifest.json` (rute tidak boleh punya `initialRevalidateSeconds: false`) dan tidak adanya berkas `.body`; guard-nya diasersi pada konfigurasi segmen rute, bukan pada komentar.
- **[26-10-22 · Test/Branding-Audit]** Berkas test 2FA baru memuat label `otpauth` ter-encode, dan `tests/branding.test.ts` merah: pemindai hostname merek membaca SELURUH source, sehingga potongan setelah tanda persen plus angka dibaca sebagai prefiks domain; baris MEMORY yang panjang juga terpangkas 120 karakter lebih dulu, jadi surel merek di ujung baris tidak terlihat oleh filter. → **Root Cause**: audit merek memindai source + dokumen (termasuk berkas test dan MEMORY.md) dengan regex longgar, dan pesan kegagalannya memotong baris sebelum difilter. → **Invariant Rule**: jangan menulis label URI ter-encode maupun nama domain dengan angka menempel di source/dokumen; bangun dan assert URI lewat `new URL(...)` supaya literal ter-encode tidak masuk berkas, dan jalankan `tests/branding.test.ts` setiap kali menambah berkas atau entri yang menyebut domain/surel merek.
- **[26-10-22 · Git/Pre-Push-Guard]** Hook memindai `origin/main..HEAD`, sehingga push dari repo/cabang tanpa `origin/main` tidak dipindai sama sekali (diff gagal, `|| true` menelan error) dan secret yang ditambahkan lalu dihapus antar-commit lolos karena hanya selisih ujung yang dibandingkan. → **Root Cause**: rentang dipilih dari asumsi nama ref, bukan dari daftar ref yang benar-benar dikirim git lewat stdin. → **Invariant Rule**: hook pre-push wajib membaca stdin (local ref/sha, remote ref/sha), memindai per-commit (`git log -p --pretty=format:` + `-m` agar diff merge ikut), memakai `--not --remotes` saat remote sha nol atau objeknya tidak ada di clone, melewati penghapusan ref, dan menyimpan hasil filter `^\+` satu kali ke berkas sementara supaya tiap pola tidak menjalankan ulang `git log`; ujinya lewat repo sementara + stdin hook, bukan `bash hook` tanpa input.
- **[26-10-23 · Vercel/Admin-Halaman]** Ringkasan deployment dibuat dengan `uid` sebagai identitas **wajib** di skema zod, padahal payload nyata `vercel ls --json` tidak memuat `uid` sama sekali (hanya `url`, `name`, `state`, `target`, `createdAt`, `meta`). Semua test sintetis tetap hijau karena fixture-nya buatan sendiri; yang akan terjadi di produksi adalah daftar kosong tanpa satu pun galat — persis kegagalan yang paling sulit terlihat. → **Root Cause**: skema ditulis dari ingatan atas bentuk REST API, lalu diuji hanya terhadap payload karangan. → **Invariant Rule**: identitas entri pihak ketiga dibaca dengan fallback (`uid ?? id ?? url ?? name`) dan **selalu** dibuktikan dengan payload nyata yang disimpan (`vercel ls --json`, `git log`, dsb.) sebelum dianggap selesai; fixture sintetis tidak membuktikan bentuk data eksternal.
- **[26-10-23 · Shell/Pola-Guard]** Pola regex yang dirangkai dalam hook sempat ditulis `mongo_pattern="a" "b" "c"`; `bash -n` menyatakannya bersih, tetapi saat dijalankan baris itu **menjalankan** `"b"` sebagai perintah (`[^:@[:space:]]+:: command not found`) lalu variabel polanya kosong sehingga guard gagal di setiap push. → **Root Cause**: `VAR=nilai kata` adalah assignment diikuti perintah, bukan penggabungan string; `bash -n` hanya memeriksa sintaks, bukan arti. → **Invariant Rule**: rangkai pola dengan tanda kutip **berdampingan tanpa spasi** (`"a""b""c"`) dan buktikan dengan MENJALANKAN hook pada repo sementara — `bash -n` tidak cukup; karakter `+` pada ERE juga ditulis `[+]`, bukan `\+`.
- **[26-10-23 · CI/Git-Hooks]** Menaruh `npm run hooks:check` **sebelum** `npm ci` di CI akan selalu gagal: hook dipasang oleh lifecycle `prepare` yang baru berjalan saat `npm ci`, jadi checkout bersih memang belum punya `.git/hooks/pre-push`. → **Root Cause**: gerbang drift diperiksa sebelum langkah yang membuat keadaan yang ingin diperiksa. → **Invariant Rule**: `hooks:check` wajib berada SETELAH `npm ci`; gejala "hook tidak sinkron" di checkout bersih berarti urutan langkahnya salah, bukan hook-nya.
- **[26-10-23 · Git/HooksPath-Bersama]** `npm run hooks:check` melaporkan drift di repo ini padahal `scripts/githooks/pre-push` sudah versi terbaru: salinan yang dijalankan git berada di `~/.git-templates/hooks` (dari `core.hooksPath` global) dan checkout lain yang masih memegang versi lama menimpanya lewat `prepare` saat `npm install`. → **Root Cause**: `core.hooksPath` global adalah keadaan bersama antar-repo, sehingga installer dari checkout mana pun menulis ke berkas yang sama. → **Invariant Rule**: jangan mempercayai isi hook terpasang sebagai bukti versi repo; jalankan `node scripts/install-git-hooks.js` lalu `npm run hooks:check` sebelum push, dan perlakukan drift pada `core.hooksPath` global sebagai kemungkinan timpaan dari checkout lain — bukan sebagai bug hook sumber.
- **[26-10-22 · Data/Env-Target]** Permintaan "hapus kategori dari database" dieksekusi pada `DATABASE_URL` lokal yang menunjuk **db dev** di cluster Atlas yang sama dengan produksi, bukan db **`jasakite`** milik Vercel: situs live tetap menampilkan 10 kategori dan data dev (46 jasa, 244 pesanan, 126 ulasan) yang justru hilang. → **Root Cause**: dev dan prod berbagi host (`ferz.bj80suv.mongodb.net`), sehingga "host Atlas" disalahartikan sebagai "database produksi"; nama database di path URL tidak pernah dibandingkan, dan README menyebut `jasakite` tanpa dicek terhadap `.env`. → **Invariant Rule**: sebelum operasi data destruktif, cetak dan bandingkan **nama database** (`new URL(DATABASE_URL).pathname`), bukan hanya host; ukur target dengan satu query read-only, lalu setelah eksekusi buktikan lewat permintaan ke URL produksi — perubahan yang tidak muncul di live berarti targetnya salah, dan verifikasi HTTP harus diulang sampai cache ISR lewat (bukan disimpulkan dari satu permintaan).
