# 📜 Anti-Slop Technical Documentation Standard

## Objective
Author developer documentation that reads as if written by a veteran Systems Engineer or Open-Source maintainer, stripping all boilerplate sycophancy.

## Prohibited AI Buzzwords & Tropes
Never use the following terms in READMEs, RFCs, or PR descriptions:
- `delve`, `harness`, `cutting-edge`, `effortless`, `seamless`, `game-changer`
- `comprehensive solution`, `robust ecosystem`, `testament`, `crucial`
- Emojis at the start of every single bullet point
- Robotic closing sentences: *"In conclusion, this provides a foundation..."*

## Principles of High-Density Technical Writing
1. **Fact-First**: Open directly with what the tool does, its inputs, and its outputs.
2. **Deterministic Commands**: Every terminal command in the README must be copy-paste executable against the real repository without modification.
3. **Architecture Reality**: Diagrams must represent actual module dependencies and data flows, not generic cloud boxes.
4. **Direct Headings**: Use `Installation`, `Configuration`, `API Reference`, `Verification`, not marketing headers like `Why Choose Us`.
